## 四、概要提取

- ⭐⭐ **外部路径字典与我方实测逐条对上**：外部字典含 `.env` / `.git/config` / `phpinfo.php`；我方 11-14 实测 `.git/config`、11-15 实测 `.env.backup` + `phpinfo.php` + `/docs/phpinfo.php` —— **三天内连续命中同一份字典的三个条目**，这不是巧合。
- ⭐ **攻击基础设施的特征决定了防御方式**：3,158 个云实例 / 92 个网段 / 43 国 / 3,299 种 UA / 36,000 端口 —— **单 IP 黑名单基本无效**；但 JA4H 指纹 `ge11nn0500_9af7e0472034` 稳定，**是唯一可靠的归并特征**。
- ⭐ **"开机—猛扫两天—关机"是可复用的攻击模式** —— IP 黑名单在其关机后完全失效，静态黑名单覆盖不了这类攻击。
- **我方 11-15 新增 5 次拉黑，全部与"敏感文件探测"相关**：4 次 Info Leak（`.env.backup` / `phpinfo.php` ×2 / `test.txt`）+ 1 次 File Inclusion；**黑名单 178→183，增删一致、失败 0**；白名单 56 全天 ±0。
- **暴露面命中已扩展到 3 个不同站点**：兆瓦快链（`182.140.209.35:18443`，两天连续被探）、续费商城（`www.pingreenmall.com:3443`，43 次/5h）、品行者（`ptm.pinnenger.com`，**该请求被放行**）。
- ⚠️ **判定链有缺口**：`8.129.101.248` 的 `/d/txt/test.txt` **被 WAF 放行**，LLM 主模型与兜底模型**双双失败**，原文明确写"无法确认是新型攻击还是正常业务访问"，仍被 v15.4 兜底拉黑 —— **既有漏放行风险，也有误拉黑风险**。

## 五、主要观点

**原文主张**

- HoneyLabs（经主信源转述）：CVE-2026-4020 只是**凭据收割机字典里最新的一条**；"当下一个未授权信息泄露漏洞发布时，它会被加进去，在下一轮扫描中自动跑一遍"—— **字典本身比单个漏洞重要**。
- HoneyLabs（同上）：561/566 个 IP 共享同一 JA4H 指纹，说明"**566 个看起来来自不同地方的攻击者，实际上是同一个客户端**"；攻击者刻意烧掉 IP 与 UA 两个防御维度；87% 流量来自 Google Cloud 账号舰队，"不是被入侵的路由器僵尸网络 —— 这是一个在云上主动启动的付费（或盗用）账号舰队"。
- HoneyLabs（同上）：**"如果发现这个指纹或者 .env 文件曾被读取过 —— 假设所有密钥都已泄露，立即轮换。"**
- SecureNow（副信源 2）：这类 bot 请求"**是否重要取决于有没有返回真的 200**……任何一条返回真 200 就是一起事件，而不是噪声"。
- 人人代码（副信源 3）：phpinfo / 探针遗留是"**根因是调试/探针文件遗留在公网**"；处置第一步就是"**全搜**：find 站点目录找 phpinfo.php、*.php 探针、test.php、.env 备份等敏感文件"。
- CISA 代理执行助理局长 Butera 的同类论断（见 [cisaRefrigerationColdChain](cisaRefrigerationColdChain-2026-11.md)）："**每一个依赖制冷与监测系统的组织都应假定自己可能是目标。**"

**我方判断**

- 🔴 **暴露面判定：我方在暴露面（探测层面），但"已泄露"未证实**。三问全过：① 组件在我方技术栈里（PHP/静态资源目录是真实存在的站点形态）；② 是**对外暴露**（WAF 记录的是公网请求，Host 为我方三个业务域名）；③ 路径可达（**规则命中且 Deny 说明请求到达了 WAF**，但**源站是否 200 我方没有观测数据**）。
  → **结论必须写清楚**：**"我方三个站点正在被系统性探测"是已证事实；"我方存在可访问的 `.env`/`phpinfo.php`"是待证事项。** 后者必须由源站自查回答 —— 这正是 P0 自查要补的那一栏。
- 🔴 **P0 自查范围必须再扩一档**：既有范围是 `.svn/`（11-12）→ `.git/`（11-14）→ **本期必须加 `.env` 家族（`.env`、`.env.backup`、`.env.local`、`.env.production`）+ `phpinfo.php` 家族（`/phpinfo.php`、`/docs/phpinfo.php`）+ 中文探针页（`tz.php`、雅黑探针等）**。**理由不是猜测，是外部字典逐条对上**。
- ⭐ **"字典 > 单个漏洞"这个判断必须写进防守策略**。我方现在（也一直）是"**一次攻击即自动拉黑单 IP**"，本期实测证明这条路线**正在被专门针对**：3,158 实例 / 3,299 种 UA / 92 网段 —— 单 IP 黑名单对他们几乎零成本。**真正能挡的是 JA4H 类请求结构指纹 + 路径字典的批量拒绝规则**，不是拉黑更多 IP。
- ⚠️ **`8.129.101.248` 的记录暴露了一个流程问题，不只是一个攻击**。它同时说明：① Info Leak 规则**未覆盖** `/d/txt/test.txt` 这类路径（**放行**）；② LLM 主模型 + 兜底模型**双双失败**时，兜底机制仍然拉黑。**"不确定即拉黑"会误伤正常业务路径**（`/d/txt/` 形态上极像静态资源），这与我方"不误封业务"的要求直接冲突。**这一条应与暴露面自查分开处理 —— 它是误报治理，不是暴露面。**
- ⭐ **`35.241.77.208` 的 43 次/5h 是本周唯一的高频单源，且探的是子目录变体**（`/docs/phpinfo.php`）—— 说明扫描器**不只扫根路径，在做路径前缀枚举**。**这意味着"只封 `/phpinfo.php` 这一条路径"是不够的**，封禁必须覆盖**路径变体族**。
- ⚠️ **不要外推**：CVE-2026-4020 本体是 WordPress Gravity SMTP 插件，**不在我方技术栈内**。本文采信的是**攻击基础设施与路径字典**，不是这个漏洞。
- ⚠️ **不要下"已泄露"结论，也不要下"扫描只是噪声"结论**。副信源 2 明确："任一返回真 200 就是一起事件，而不是噪声。"**我方现在的状态是"不知道"** —— 而"不知道"正是 P0 自查要解决的东西。
