## 五、主要观点

**原文主张**

- 报告（内部脚本，无分析结论）：攻击源 IP 4 个，全部为 🛡️ Threat Intelligence，需拉黑 0、忽略 4；四个 IP 攻击次数均 1 次，且处理记录全部指向既有黑名单条目；白名单 56（±0）；黑名单 WAF 实际 196 / 备份总 387（活跃 196、已删除 191）/ 本次新增 0 / 失败 0；今日新增 1 个 IP（`31.42.176.198`，📁 Info Leak，AI 自动封禁，「本次窗口无命中」）。
- fast-skip 机制说明（报告原文）：ATTACK_TYPES_IGNORE 列表内类型「**默认不二次分析、不走 LLM、不拉黑、不推送。SafeLine WAF 默认拦截即可**」。

**我方判断**

- ⭐⭐⭐ **「连续两日需拉黑归零」这个读数，必须和它的成因一起入库，否则会变成一个危险的结论。** 单独看「两天零新增拉黑」，运维会判定「威胁强度下降」；但把成因摆出来 —— **这两天的四个 IP 全是 fast-skip 的 Threat Intelligence，且全在既有黑名单里、全是 1 次低频试探** —— 真实含义是：**外部威胁强度读数在我方这一侧被 fast-skip 通道滤掉了**。**外部强度与我方暴露面缺陷是两条独立变量**（库内 11-24 已立此对照）：库内 11-15~11-18 记着我方主站连续命中（Info Leak **Allow 未拦截** → 反序列化 **Allow 未拦截** → SSRF Deny → `policy_rule44` 误拦第三次），**这三条待闭环项到本期一条未推进**。→ **动作：日报与台账里，「需拉黑类型归零」这一条必须与「fast-skip 占比」和「我方站点命中条数」并排出现，缺一不可读。**
- ⭐⭐⭐ **「四个源 IP 全是既有黑名单 IP、全是 1 次」这条内部证据比任何外部报告都有用。** 它用最简单的方式印证了库内 11-16 的核心结论：**黑名单里堆着的 IP 在做长期低频试探，而单 IP 封禁对整体无效**（每个 IP 都只打 1 次，说明对方在轮换或摊薄）。**因此「零新增拉黑」不是防守成功的证明，是黑名单机制正常工作的证明 —— 这两件事完全相反。** → **动作：WAF 台账的「有效」判据必须从「新增拉黑数」改为「**我方站点命中中被正确拦截的比例**」，而后者恰恰是报告目前不提供的字段** —— 这就又回到采集脚本的缺口上。
- ⭐⭐⭐ **采集脚本缺口是本期最该被推动的事，因为它已经连续第 9 期在造成实际损失。** 库内 11-17 记的是「漏采需确认报文节」，本期表现为「只产出类型分布」—— **本期这条情报里，九成内容（IP、次数、黑名单基线、白名单、窗口口径）全靠人工从报告里补**。**更严重的是：脚本把 `source_url` 留空、`severity` 标 `low`，而 pipeline.md 明确规定「每条原始情报必须包含 source_url，缺字段直接丢弃」** —— **按现行规范，这条情报本应被直接丢弃。** → **动作：这是本期唯一一条我认为应当升格为「采集管线待办」的条目，而不是「观察项」**：`collect.py` 至少要补齐 source_url（内部报告文件路径）、攻击类型/IP 数、需拉黑数、黑名单活跃/总数/已删除、白名单数、窗口口径六个字段。它不产专项整改，但它是**后续所有安全域条目的数据管道**，值得单独立一条待办。
- ⭐⭐ **黑名单净增长（活跃 +1）这件事本身不大，但它和「新增 IP 属窗口外补录」并排出现，含义就变了。** 若只看「活跃 196」，会以为黑名单在增长 = 攻击在增长；若把两条并排看：**当天实际发生的新增拉黑只有 1 个，且那 1 个的攻击发生在本轮窗口之外**。→ **动作：黑名单基线必须按「当日净增（活跃差）」与「窗口内可见新增」两列记**，否则趋势读数会系统性偏高。
- ⭐⭐ **白名单连续多期 ±0 是好消息，但也意味着这条线没有人在动。** 库内 11-24 已记「七天内豁免面规模零变化」；本期仍 56 ±0。**「没有变化」既可以读成「豁免面管理良好」，也可以读成「这条线根本没有日常动作」** —— 在一个刚发生多起「配置类缓解悄悄失效」的环境里，**我方不能默认白名单是被定期审视的**。→ **动作：登记为「待核实」—— 白名单是否有人定期复核、有无过期机制，库内无材料，不下结论。**
- ⭐ **脚本缺陷未复现是负结论，必须照记且不得升级为「已修复」。** 11-24 记的「登录失败仍报 ok 但无报告落盘」本期没有出现，**这只说明 11-25 这一轮正常**。→ **动作：维持「未验证」状态，等连续多日正常且有一次故障复现对照后再定性。**
- ⚠️ **严格边界**：本期不产专项整改，不下「我方受影响」或「我方零攻击」结论。**本篇的价值在于把库内已立的读数纪律（fast-skip ≠ 放过、报告未记录 ≠ 无命中、补录 ≠ 当日新增、负结论必须照记）用新数据再验证一轮，并把「我方侧可见度」这个结构性问题从「11-24 的一个轮的观察」升级为「连续两轮的事实」。**
