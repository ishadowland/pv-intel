- ⭐⭐⭐ **「零新增拉黑」连续三轮成立，与库内 11-24 的 6 个新增形成清晰边界；而这 6 个全部标注"本次窗口无命中"—— 这句话必须被读成一条重要的口径事实，而不是一句备注。** ⭐⭐⭐ **它意味着这批 IP 的攻击全部发生在 11-18 ~ 11-24 的巡检断档期**（16:07 轮的报告窗口本身就写着"覆盖 139.5h 断档"）。⭐⭐ **因此我方在评估 11-24 当日风险时，正确算法是：当日新增 = 0（17:37 + 20:37 两轮均无新增），断档期存量补录 = 6（已全部拉黑）**。⭐⭐ **写错的后果很具体**：如果把 6 个都算成"11-24 的攻击"，我方的攻击趋势图会被凭空抬高，而真实的当日曲线是平的。⭐⭐ **这条也说明"巡检断档"本身是一个需要被计量的事件** —— 库内 11-24 日报已经记了断档事实，但**没有记"断档期有多少攻击被延迟发现"这个量**；本篇首次提供了这个量的下界（**至少 6 个、全部为 Info Leak / File Inclusion 类型**）。

## 七、总结输出

**一句话结论**：**11-24 的三轮 WAF 巡检（16:07 / 17:37 / 20:37）全部落盘，是库内 11-18 之后第一次取得完整一日的同口径序列 —— 攻击源 IP 数 78 → 8 → 5、攻击类型从 16:07 轮的 🛡️ Threat Intelligence 72 + 📁 Info Leak 5 + 📂 File Inclusion 1 收敛为后两轮的 100% Threat Intelligence、需拉黑数归零、黑名单活跃 195（总 386、已删除 191）三轮持平、白名单 56 ±0；⭐⭐⭐ 因此库内 11-24 日报里那条被退回的「File Inclusion 进入需拉黑类型属类型分布变化」本期得到的是"未复现"的对冲读数 —— 这条负结论必须照记不省，因为运维基线恰恰需要"连续零新增"这类读数才能在异常出现时被识别，且本期顺带把「活跃黑名单 195 / 已删除 191 / 白名单 56 / 断档延迟发现数」这四个数确立为可长期复用的状态基线；⭐⭐⭐ 但三条口径必须钉死：① **16:07 轮的 6 个新增全部标注"本次窗口无命中"，其攻击发生在 11-18 ~ 11-24 的断档期内（该轮窗口本身写着"覆盖 139.5h 断档"）→ 正确算法是"当日新增 = 0、断档期存量补录 = 6（已全部拉黑）"，写错会把攻击趋势图凭空抬高**；② **三轮窗口口径不同（24h / 7h / 7h），只有后两轮可直接比**，"File Inclusion 未复现"仅有两轮 7h 窗口作证、**不得写成趋势**；③ **fast-skip 的"忽略"指的是不做二次分析、不走 LLM、不拉黑、不推送，SafeLine 仍默认拦截 → 不等于放过，但等于我方侧对这类流量没有任何可见度**，这正是库内 11-16「单 IP 黑名单覆盖度 ≈ 0」的结构性原因，也是"零新增拉黑"这一结论必须打折的理由（它只能说明没有需要拉黑的，不能说明没有攻击）。⭐⭐⭐ **本期最需要并排写的是一组对照**：连续三轮报告未记录任何我方站点命中，而库内 11-15 ~ 11-18 记着我方主站的连续命中（Info Leak **Allow 未拦截** → 反序列化 **Allow 未拦截** → SSRF Deny → `policy_rule44` 误拦第三次复现）—— **外部威胁强度与我方自身暴露面缺陷是两条独立变量，后者的进展不会因为前者下降而自动改善，而本期这三条待闭环项一条都没有推进**，故 P0 暴露面自查范围（品行者主站）不得因本期读数平静而沉底。⭐⭐ **另两条可执行增量**：17:37 轮 8 个 IP 中 6 个集中于 54.222–54.223 与 52.80 段且"已处理于"显示全是已知黑名单 IP → 库内首次取得"同一网段短时批量 + 全是旧 IP"的内部读数，精确印证库内 11-16 的结论（攻击基础设施高度复用、单 IP 封禁对整体无效 → **真正的防线必须落在协议层与应用层行为判据**），并提示**报告是逐 IP 列表、网段聚集性要靠人眼，量一大就会漏，应把"网段聚集性"加进分析口径**；以及**库内首次把 WAF 攻击类型的历史序列摆齐后暴露出口径断裂比数据缺失更麻烦**（11-17 两份是"我方站点命中事件"、11-24 与本期是"外部源 IP 类型分布"，只有后两者同口径可比），这与我方在产业域遇到的硅料/库存/产量口径冲突（6/5/5 处）是同一类病 —— **处置方式也应相同：固定每日 20:37 轮的 7h 窗口为唯一可比基线读数，其余轮次作补充**。⚠️ 边界五条：无 URL / payload / 事件 ID → 不得推断攻击手法；"零我方站点命中"的准确表述是"报告未记录我方站点命中"而非"我方零攻击"；巡检三轮成功不等于"登录失败已改硬失败退出"的缺陷已修复；`File Inclusion` 是否在 block / ignore 名单仍未确认、不得据"未复现"推断；我方无本期新增暴露面证据 → 不产专项整改、不新开产物。**
