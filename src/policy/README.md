## 采集口径

政策文件本身不是情报，**政策的约束条款才是情报**。每份文件进来必须回答：

```
这份文件 → 对我方哪条业务线 → 要求做什么 → 什么时候生效 → 谁负责
```

答不上"要求做什么"的，留在简报的"备案"区，不进本域。

### 三级分类

| 级别 | 定义 | 处理方式 |
|---|---|---|
| 🔴 **强约束** | 直接规定我方必须做的功能/流程/申报 | 立即进评审，产出需求变更或产品特性 |
| 🟡 **有影响** | 不直接约束，但改变经营参数或客户预期 | 进简报，跟踪是否升级 |
| ⚪ **备案** | 行业动态、上位规划，暂无可执行动作 | 仅存档，定期复查 |

### 重点关注的发文主体

| 主体 | 关注方向 |
|---|---|
| 国家发改委 / 能源局 | 电价机制、绿电绿证、消纳责任权重、电力市场建设 |
| 工信部 | 光伏制造行业规范条件、产能调控 |
| 国家能源局 | 分布式光伏管理办法、并网与调度 |
| 财政部 / 税务总局 | 可再生能源补贴、税收 |
| 网信办 / 工信部（安全侧） | 数据安全、关基保护、网络安全审查 —— 与[安全情报域](../security-intel/README.md)联动 |
| 省市能源局 | 地方补贴、接入方案、消纳 |

### 每份政策的落库格式

**统一用 [七段式文章结构](../meta/pipeline.md)**，政策域额外要求：

- 第 2 段事实核查**必须核文号和生效日期**（政策文号错一个数字，引用就废了）
- 第 3 段快照优先抓**官网原文**（发改委/能源局/工信部），媒体报道只作补充信源
- 第 5 段「主要观点」里，**「原文说」**摘政策原文，**「我方判断」**写这条对我们意味着什么
- 第 7 段勾选落地去向时，🔴 强约束文件**默认至少勾一项**，除非四关全不过

## 跟踪机制

- 新文件进来先判级别，🔴 级 24 小时内必须出结论
- 已有文件若临近生效日，**重新进评审**（可能已升级为强约束）
- 政策与安全情报交叉：涉及关基、数据出境、等级保护的，同步登记到安全域
