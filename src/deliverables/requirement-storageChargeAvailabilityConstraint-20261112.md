# 储能收益测算增加"可充电富裕电量"约束

> 类型：**需求变更** · 优先级：P1 · 责任人：\<待指派\>
> 来源情报：[新型电力系统的安全风险、关键问题与应对策略](../solar-industry/newTypePowerSystemSecurity-2026.md)
> 提出日期：2026-11-12 · 评审状态：待评审

## 1. 背景与证据

《新型电力系统的安全风险、关键问题与应对策略》（中国工程科学 2026, 28(5): 12-21）指出一条我方现有模型缺失的物理约束：

> 新型储能可以部分解决电力供需不平衡问题，但参与电力平衡能力与电力电量缺口程度高度相关；**电力电量缺口越大，可供储能充电的富裕电量时刻越少，则新型储能参与电力平衡能力越低**。[23]

同一文献给出的量级锚点：

> "十五五"时期末 3×10⁹ kW 新能源在晚峰时段**仅能提供不足 1×10⁸ kW 的可信出力**。

**现状**：我方 [储能收益测算四段式](feature-storageRevenueModel-20261112.md) 的峰谷套利段按"**名义容量 × 充放电时长 × 峰谷价差**"计算，隐含假设"**只要有价差，储能就能充进去、能放出来**"。

⚠️ **该假设在缺电场景下不成立**：
- 系统缺口越大 → 全网越缺电 → **可供充电的富裕电量时刻越少**
- 同时晚峰是价差最大的时候，也正是**系统最缺电、最需要储能**的时候
- 两个效应叠加 → 实际可调用容量/可用时长 **小于** 名义值

**后果**：在"晚峰价差大 + 系统紧平衡"的典型场景下，我方四段式模型会**系统性高估**峰谷套利段收益 —— 而这正是储能收益中占比最大的一段。给托管客户（尤其是配储的自发自用工商业）做收益预测时，**高估就是失真**，直接伤害定价说服力。

⭐ **注意这不是新增功能，是模型口径修正**：四段式拆分、参数来源标注、敏感度分析等能力已在现有产物里，本条只补一个**约束条件**。

## 2. 影响面

| 受影响系统/产品线 | 影响点 | 现状 |
|---|---|---|
| 品能者托管 | 储能收益测算（峰谷套利段） | 按名义容量 × 时长 × 价差，未扣可充电约束 |
| 兆瓦快链 | 储能运营看板 / 聚合测算 | 同源模型，同一偏差 |
| 售前 / 客户方案 | 储能配置建议的收益对比 | 高估 → 客户实测低于预期 → 续约风险 |
| PTM 现货交易平台 | 现货价差段（共用同一容量口径） | 未建模 |

## 3. 动作

### 做什么

- [ ] 峰谷套利段新增输入参数：`chargeAvailabilityFactor`（可充电富裕电量占比）与 `availableWindowHours`（当日实际可充/可放窗口小时数）
- [ ] 有效可调用容量 = 名义容量 × `chargeAvailabilityFactor`；有效可放时长 = `min(配置时长, availableWindowHours)`
- [ ] 参数**必须带来源标注**：系统缺电情景档位（充裕 / 紧平衡 / 缺电）/ 我方测算口径 / 用户自定义 —— 三选一，与现有四段式的参数来源标注机制一致
- [ ] **新增缺电情景档位**：同一组价格曲线在"充裕 / 紧平衡 / 缺电"三档下输出三组收益，UI 展示区间而非单值
- [ ] 敏感度分析增加 `chargeAvailabilityFactor` 作为一路敏感变量（当前仅价格波动）
- [ ] 缺电情景下的**置信度标记**：当档位取"缺电"且 `chargeAvailabilityFactor` 为估算值时，输出加"估算"标记（不允许与实测口径同权呈现）

### 不做什么（划边界）

- ❌ 不做实时充放电调度与 SOC 仿真（属 PTM / 站控侧，本变更只负责测算口径）
- ❌ 不预测未来某日是否缺电（缺电情景由**用户或交易平台提供**，我方只提供档位映射）
- ❌ 不改动现货价差段、辅助服务段、容量电价段的计算逻辑（容量电价是按可用容量付费，与可充电窗口无关）
- ❌ 不引入新的外部数据源（缺电情景档位若需外部输入，先由 [兆瓦快链聚合](../policy/ndrcNewEnergyConsumptionGuidance-2026.md) 侧提供，本变更只消费）

## 4. 验收标准

- [ ] 同一组输入下，`chargeAvailabilityFactor = 1` 且 `availableWindowHours ≥ 配置时长` 时，结果与现有四段式模型**完全一致**（回归用例，误差 < 0.01%）
- [ ] 缺电档位下峰谷套利段收益**严格小于**充裕档位，且差额与参数变化一致（可用手算反证）
- [ ] 三个档位输出为**区间**展示，不覆盖历史单值结果（老结果可复现）
- [ ] 每个输出参数都带来源标注，可追溯到具体档位或用户输入
- [ ] 敏感度分析输出包含 `chargeAvailabilityFactor` 一路，且单参数变化时其余段收益**不受影响**（四段独立开关仍然成立）
- [ ] 回归用例覆盖四场景：充裕 / 紧平衡 / 缺电 / 参数缺失

## 5. 排期

| 阶段 | 时间 | 产出 |
|---|---|---|
| 需求与口径对齐 | 1 周 | 三档缺电情景的档位定义 + `chargeAvailabilityFactor` 取值口径文档 |
| 设计 | 3 天 | 引擎参数接口 + UI 三档展示稿 |
| 开发 | 2 周 | 峰谷套利段约束 + 档位切换 + 敏感度扩展 + 回归用例 |
| 上线 | 随 R2026.12 | 灰度：先品能者托管（与四段式升级同步上线，避免两版口径并存） |

## 6. 风险与依赖

- **依赖**：需要与 PTM 团队确认现货行情/调度信息中是否已有可用的"富裕电量"或缺电档位信号可复用；若无可复用信号，本变更的档位只能由用户手工指定（需在 UI 明确说明"手工档位为估算"）
- **风险**：缺电档位的映射阈值若由我方自定，存在"用一个未经校准的系数修正另一个未经校准的假设"的风险 → **档位必须可由外部数据覆盖**，且默认值只做保守取值
- **风险**：与 [四段式升级产物](feature-storageRevenueModel-20261112.md) 的排期耦合 —— 两者同期上线，避免客户侧看到两个口径的收益数字
- **依赖（口径）**：本文的论据来自一份**战略咨询研究**，其中"缺口越大储能越充不进电"的机制成立、量级需自建 —— **档位阈值不引用该文献的具体数字**，我方需用自己的历史数据回测确定
