# 储能收益测算模型升级为四段式

> 类型：**产品特性** · 优先级：P1 · 责任人：\<待指派\>
> 🟡 **待复核（2026-11-12 新口径）** —— 本产物属产品线级，库内产品特性与场景材料不足，转评审阶段暂缓；待材料积累后复核。
> 来源情报：[发改委/能源局促进新能源消纳和调控指导意见](../policy/ndrcNewEnergyConsumptionGuidance-2026.md)
> 提出日期：2026-11-12 · 评审状态：待评审

## 1. 背景与证据

2026-11-10 发改委、能源局《关于促进新能源消纳和调控的指导意见》明确：

> "加快现货和辅助服务市场建设……激励发用两侧资源主动参与系统调节"
> "健全完善煤电、抽水蓄能、**新型储能**等调节性资源**容量电价机制**"
> "2026 年起，新能源将全面参与市场，入市装机占比、发电量占比均将超过 80%"

**现状**：我方储能收益测算模型基于「峰谷价差套利」单一逻辑。而政策已把储能收益来源扩展为四类：

| 收益类型 | 政策依据 | 当前模型是否覆盖 |
|---|---|---|
| 峰谷价差套利 | 已有 | ✅ |
| **现货市场价差** | "加快现货…市场建设" | ❌ |
| **辅助服务补偿** | "激励…参与系统调节" | ❌ |
| **容量电价** | "健全…新型储能…容量电价机制" | ❌ |

**后果**：在 2026 年新能源全面入市的新环境下，用单一峰谷逻辑给客户做储能收益预测，**会系统性低估收益**（漏掉三项），同时**无法回答客户最关心的"市场化后还赚不赚钱"**。随着分布式、储能、虚拟电厂成为可入市主体（政策明确支持），我方若不能在工具侧给出市场化收益口径，就会失去对托管服务定价的话语权。

## 2. 影响面

| 受影响系统/产品线 | 影响点 | 现状 |
|---|---|---|
| 品能者托管 | 储能资产收益测算 | 单一段落式输出 |
| 兆瓦快链 | 储能运营看板、聚合测算 | 无辅助服务/容量电价科目 |
| PTM 现货交易平台 | 现货价差收益归集 | 未建模 |
| 售前/客户方案 | 储能配置建议的收益测算 | 用单一段落做对比 |

## 3. 动作

### 做什么

- [ ] 收益测算引擎拆分为四个独立计算段：峰谷套利 / 现货价差 / 辅助服务 / 容量电价
- [ ] 每段支持独立开关与独立参数（避免"某段没数据就整体算不出"）
- [ ] 参数来源可标注：政策默认值 / 市场实际值 / 客户自定义（用户必须知道数字从哪来）
- [ ] 输出从"单值"改为"分段 + 合计"，UI 展示各段贡献占比
- [ ] 新增"敏感度分析"：给定价格波动区间，输出收益区间而非点估计

### 不做什么（划边界）

- ❌ 不做实时行情接入与自动下单（那是 PTM 的职责，本特性只负责测算口径）
- ❌ 不做辅助服务的资格准入判定（涉及企业资质，不在产品范围）
- ❌ 不替代客户自有投资测算模型（提供口径与参数，不接管逻辑）

## 4. 验收标准

- [ ] 四段收益可独立开关，关闭任一段不影响其余段计算
- [ ] 同一组输入下，分段结果之和 = 合计结果（误差 < 0.01%）
- [ ] 每个输出参数都带来源标注，可追溯到"政策默认值"或具体市场数据
- [ ] 敏感度分析输出区间，且给定零波动时退化为点估计
- [ ] 回归用例覆盖：仅峰谷段可用、四段齐全、参数缺失三��场景

## 5. 排期

| 阶段 | 时间 | 产出 |
|---|---|---|
| 需求与口径对齐 | 2 周 | 四段口径定义文档 + 参数来源清单 |
| 设计 | 1 周 | 引擎接口设计 + UI 稿 |
| 开发 | 3 周 | 引擎 + UI + 回归用例 |
| 上线 | 随 R2026.12 | 灰度：先品能者托管 |

## 6. 风险与依赖

- **依赖**：需要与 PTM 团队确认现货价差数据的可得性与口径（现货数据是否可商用、延迟多少）
- **风险**：政策细则（各省）尚未落地，容量电价的具体机制可能再调整 → 参数必须做成可配置，不能硬编码
- **风险**：若把政策默认值写死，未来政策变化会导致静默错误 → 参数需带生效日期与来源
